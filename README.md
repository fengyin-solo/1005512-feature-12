# 制药企业洁净区与批生产记录管理平台

面向洁净区环境监测、批生产记录编录、物料放行、偏差与变更控制、灭菌与清洁验证、成品检验与年度质量回顾的一体化药品生产质量管理工作台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `pharma-cleanroom:entries` 这一项，或调用 `resetModule(模块)`。

## 水系统月报分册

工艺用水监测模块在通用机制之外，另有一套月报口径，领域配置集中在
`frontend/src/data/water-config.ts`，专用读写在 `frontend/src/api/water-service.ts`：

- **按类别分线取样**：纯化水（周一早班）、注射用水（周三中班）、灭菌注射用水（周五早班）、
  饮用水（周二早班），各线有独立取样点与内控限度；登记时取样日期必须与班次（固定星期）对齐，
  不对齐挡回，检验人按 ISO 周在四人花名册上轮换并自动派工。
- **状态顺流转、越级挡回**：待取样 → 检测中 → 已合格 / 不合格；不合格或检测中微生物越界可
  打回重填，回到待取样并清空检测项。微生物限度越界只能打回重填，不能判合格或不合格。
- **微生物各入口同一份**：同一水系统类别、同一取样日期的多个取样点共用一个微生物结果，
  录入时自动同步，改成不同数值会被拒。
- **月报分册导出**：按月份导出一个 Excel 工作簿（SpreadsheetML `.xls`，Excel/WPS 可直接打开外发），
  含封面、四张分册与导出台账；每册标注水系统类别与取样日期，列明取样点、电导率、总有机碳、
  微生物限度；某类别当期无记录时出具一页正式空期说明（含当月排班日期），绝不出空壳文件。
- **重复导出只算一次**：导出台账（`pharma-cleanroom:water-export-ledger`）记录已导出的
  「记录编号+月份」，再次导出只列新增、不重复计数，需要全量重出时勾选「连同已导出记录重新出全量册」。
- **结论反映**：已合格 / 不合格的水质结论自动以「【水点】」条目反映到洁净区环境监测清单，
  打回重填后对应条目撤销。
- **历史兼容**：历史电导率手抄文本（如「10.8（25℃手抄）」）原样保留、原样进册，不做数值换算或越界判定。
- 领域规则回归测试：`cd frontend && npm run test:water`（59 条断言）。
